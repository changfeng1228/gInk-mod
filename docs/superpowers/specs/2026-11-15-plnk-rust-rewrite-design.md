# plnk Rust 重写设计

**状态：** 提案，待用户批准  
**日期：** 2026-11-15  
**工作名：** `plnk`（名称可调整，不影响技术方案）

## 1. 背景与初衷

现有程序是 gInk 1.1.1 的修改版，提供全屏批注、工具栏、截图与贴图。它目前依赖 .NET Framework 3.5、x86 `Microsoft.Ink` COM、WinForms/GDI。近期动画优化已证明可以提高回调频率，但全屏 GDI 画布、旧 COM 笔迹组件和逐帧程序驱动动画仍限制长期维护与原生性能。

本次重写不是为了更换界面或堆叠功能，而是保留“轻量、随叫随到、直接在小屏幕上书写和贴图”的初衷，并建立可持续的原生技术底座。

已测量的当前基线：托盘空闲工作集约 37.9MB、私有内存约 17.6MB；主显示器逻辑分辨率 1707×1067、150% DPI。正式验收必须在相同机器上重新测量，不能把这些单次数据当成稳定基准。

## 2. 用户已决定的事项

- 使用 **Rust 完整重写**，不再比较其他语言。
- 先编写整体开发计划，批准计划后才创建产品代码或安装依赖。
- 目标是完整保留现有程序的实用功能，同时降低资源占用并提高响应和动画流畅度。

## 3. 本设计作出的技术决定（未视为用户额外要求）

- 首个正式版只承诺在**用户当前 Windows 11、鼠标书写、当前显示器**上通过验收；压感笔、触摸和实体多显示器保留实现，但无设备项目标为“未验证”，不阻塞本次发布。
- 用户优先级是更好的性能、响应和 240Hz 动画；鼠标笔迹要求自然、低延迟、无明显抖动，不要求与 Microsoft.Ink 像素完全一致。
- 首个正式版不承诺 Windows 10 已验证支持；保留 Windows 10 1607 API 下限设计，但不为此增加 VM 或旧系统发布门。
- 使用 Microsoft 官方 `windows` crate 直接调用 Win32、Direct2D、DirectWrite、DirectComposition、DXGI、WIC 和 Pointer Input，不使用 WebView、Electron、Qt、WPF 或通用 GUI 大框架。
- 采用原生双窗口层，而非每帧重绘整个虚拟屏幕。
- 保留旧版 INI、笔刷、热键和语言数据的语义；首次运行可导入旧配置，但绝不改写旧 gInk 配置。
- 新程序使用独立 exe、互斥体和配置目录，与旧版并存；切换启动项必须由用户明确批准。

## 4. 目标

### 4.1 功能目标

正式版实现必须覆盖旧版功能对齐清单，验收分为“当前设备必测”和“无设备未验证”两类：

- 托盘启动/退出、单实例、全局热键、笔/橡皮/指针/平移模式；
- 多笔刷、颜色、透明度、宽度、荧光笔、压感（硬件支持时）、笔迹显示/隐藏；
- 笔画擦除、清空、撤销/重做、工具栏停靠/取消停靠与拖动；
- 矩形截图、保存、复制到剪贴板、截图后行为选项；
- 独立贴图窗口：移动、角部/滚轮缩放、透明度、置顶、复制、保存、关闭；
- 选项界面、多语言、图标与工具栏布局选项、自动滚动及 DPI/多显示器行为；
- 原配置、默认保存目录和用户已有贴图/截图工作流的连续性。

详细功能矩阵由实施计划 Task 1 固化；任何“旧版有、重写版遗漏”的功能都必须显式记录为接受或延期，不能静默消失。当前发布门只要求鼠标、当前 Windows 11 和当前显示器项目全部通过；压感笔、触摸和实体多显示器没有设备时标为“未验证”，不得声称已验收，也不阻塞当前配置发布。

Undo 恢复语义仅覆盖**同一进程内关闭再打开批注**；不保存笔迹/历史到磁盘，不承诺退出或重启程序后恢复。

### 4.2 性能目标（用户当前机器、Release、单显示器）

| 指标 | 正式版目标 | 测量方式 |
|---|---:|---|
| 托盘空闲私有内存 | ≤ 25MB | 30 秒稳定后取进程私有字节 |
| 托盘空闲工作集 | ≤ 35MB | 同一采样窗口 |
| 书写模式私有内存（不含显存） | ≤ 50MB | 1000 条混合笔画后测量 |
| Release exe | ≤ 8MB（语言资源外置时） | 文件大小；构建产物同时记录 |
| 冷启动到托盘可用 | ≤ 150ms | 20 次冷启动，取 p95 |
| 托盘无操作 CPU | ≤ 0.5% | 30 秒平均值 |
| 动画期间应用 CPU | ≤ 2% 单个逻辑核心（CPU 时间 ÷ 动画墙钟时间） | 同时记录进程原始 CPU 百分比与归一化值 |
| 240Hz 可见动画帧间隔 | 中位 ≤ 4.2ms，p95 ≤ 8.4ms | 240fps 屏幕捕获/DWM 时间戳，不用回调频率代替 |
| Pointer 消息到提交绘制的 CPU 延迟 | 中位 ≤ 2ms，p95 ≤ 4ms | Release 性能探针；不含数字化仪硬件延迟 |
| 资源泄漏 | 同一常驻进程内 100 次打开/退出批注后，句柄、线程、内存回到预热基线 ±5%；另做 20 次完整冷启动 | 自动化 soak 与冷启动测试 |

性能目标若与硬件能力冲突，必须记录实测数据和原因，不得用提高 CPU 占用或省略测试来“达标”。

## 5. 非目标与反目标

- 不做 macOS/Linux、跨平台抽象层或 Windows 7 兼容。
- 不增加云同步、协同编辑、OCR、文本/图形编辑器、插件系统、账号或后台服务。
- 不重设计工具栏视觉和交互，不用“现代化 UI”扩大范围。
- 不要求管理员权限，不安装 Windows 服务，不注入其他进程。
- 不在功能未对齐时替换旧版启动项或删除旧版。
- 不通过常驻高频轮询、无界线程队列或每帧全屏位图上传换取表面帧率。

## 6. 总体架构

### 6.1 两个原生窗口层

1. **InkOverlayWindow**：覆盖虚拟屏幕或按显示器拆分的透明窗口，负责 Pointer/Mouse 输入与笔迹呈现。静态笔画进入缓存位图，活动笔画单独绘制，只提交脏矩形。指针模式通过窗口样式切换输入穿透，不做逐像素命中测试。
2. **ToolbarWindow**：尺寸仅为实际工具栏的原生顶层窗口，负责按钮、停靠和滑入/退出。DirectComposition 的变换动画由 DWM 按显示器合成节奏执行；程序只设置起点、终点、时长与缓动，不运行 4ms 动画线程。

PinWindow、选项窗口、截图选择层各自独立，不共享“所有内容都画在全屏位图上”的旧架构。

### 6.2 线程与状态

- 单个 UI 线程拥有窗口、输入、笔迹模型和 D2D/DComp 对象，避免全局 `Arc<Mutex<App>>`。
- 截图编码、文件 IO 可使用有界工作队列；结果通过 `PostMessageW` 返回 UI 线程。
- 不引入 Tokio 或通用异步运行时；使用标准库线程和有界 `sync_channel`。
- 动画只保存绝对开始时间、时长、起点和终点；屏幕动画由 DComp 执行，模型动画使用单调时钟。

### 6.3 图形与输入

- Direct2D/DirectWrite/DirectComposition/DXGI 负责呈现与文本，premultiplied alpha。
- `WM_POINTER` / `GetPointerPenInfo` 处理笔、触摸和鼠标；支持压感、擦除端及硬件能力探测。无压感设备使用固定宽度。
- 物理像素用于笔迹和截图坐标；DIP 仅用于工具栏与选项布局。所有窗口几何进入统一 DPI/虚拟屏坐标边界。
- 笔迹由点列、工具样式与平滑几何组成；撤销/重做记录编辑命令，不在每帧克隆全部笔迹。
- WIC 负责 PNG 编解码；截图原型同时验证 GDI 兼容路径与 DXGI Desktop Duplication 路径，再固定正式路径。

### 6.4 设置与资源

- `Settings` 是唯一强类型配置入口；旧 INI 解析、默认值、校验和迁移有 golden fixtures。单个非法值只回退该键并警告，其他有效项继续导入；文件不可读才作为整体错误处理。
- 新配置默认位于 exe 同级的 `data/` 子目录，保持便携性；该目录不可写时回退 `%LOCALAPPDATA%\plnk`。导入过程只读旧 gInk 文件。语言文件保留现有 31 个文本资源，缺失键回退英语并记录。
- 保留 gInk 的 MIT 许可证与 Weizhi Nai 版权声明；发行包继续附带 `license.txt`，重用图标、翻译或行为设计时不移除来源说明。
- 错误日志写入新程序自己的数据目录，日志大小有上限；不上传任何数据。

## 7. 拟定代码边界

实施时在仓库内新增独立 `plnk/` Cargo 包，旧 `src/` C# 程序保持可构建：

```text
plnk/
  Cargo.toml / rust-toolchain.toml / build.rs
  src/
    main.rs              # 入口、单实例、顶层错误处理
    app.rs               # 应用生命周期与模式状态机
    settings.rs          # 强类型设置、默认值、旧版导入
    platform/            # Win32 窗口、DPI、托盘、热键、剪贴板
    gfx/                 # D2D/DComp 设备、表面、脏矩形、动画
    input/               # Pointer 规范化、鼠标/笔/触摸状态
    ink/                 # 笔迹模型、几何、历史、擦除
    ui/                  # 工具栏、选项、贴图、截图选择
    snapshot/            # 捕获、WIC 编码、保存
    telemetry.rs         # 有界日志和 Release 性能计数
  assets/                # 图标与语言资源
  tests/                 # 单元测试、Windows 集成测试与 fixtures
scripts/                 # 仓库级验证、性能测量和打包脚本
```

运行时依赖原则上仅 `windows` crate；新增 crate 必须说明其替代的系统 API、体积收益和必要性。

## 8. 验证策略

- **单元测试：** 配置、几何、笔画平滑、脏矩形、撤销/重做、动画进度、DPI 坐标变换、语言回退。
- **Windows 集成测试：** 真实窗口消息、输入穿透、热键、剪贴板、截图、贴图、句柄销毁/重建、100 次开关。
- **视觉测试：** 关键 DPI 下 golden screenshot（容差比较），入场/退出位置及最终像素。
- **性能测试：** Release 专用探针，同时记录应用时间戳和可见呈现；不得以定时器回调数冒充满屏帧率。
- **当前设备人工验收：** 鼠标慢速直线、快速曲线、锯齿、圆、短点、荧光笔重叠；用户与旧版并排比较，接受自然、低延迟、无明显额外抖动即可，不要求像素一致。
- **未验证硬件：** 压感笔、触摸和实体多显示器只保留自动化/模拟测试与实现说明；没有设备时明确标记“未验证”，不阻塞当前 Windows 11 + 鼠标发布。
- **兼容测试：** 当前用户配置的脱敏副本、旧版默认配置、损坏/缺项配置、长笔迹与多张贴图。

## 9. 阶段与退出条件

1. **基线与技术验证：** 固化旧版行为；Rust 原型验证透明输入层、DComp 240Hz、压感和 DPI。未通过则停止全量重写。
2. **应用骨架：** 单实例、托盘、设置导入、热键、日志和本地验证门（已有 Windows CI 时再接入）。
3. **可书写 MVP：** 原生层、笔/鼠标笔迹、工具栏、撤销/重做、擦除、清空。
4. **工作流对齐：** 指针/平移、停靠、选项、多语言、自动滚动。
5. **截图与贴图：** 选区、保存/复制、贴图完整交互、多 DPI。
6. **硬化与发布：** 性能、兼容性、泄漏、安装包、并存试用、用户验收。

每个阶段都有独立可运行产物和回滚点；详细任务、接口与测试见配套实施计划。

## 10. 发布与回滚

- Rust 版先以便携目录运行，旧版保持启动项；测试时使用不同互斥体并避免热键冲突。
- 只有当前设备功能矩阵与性能预算通过并经用户试用批准后，才修改启动项；无设备项目必须保持“未验证”，不得写成通过。
- 回滚只需恢复旧启动项；旧 exe、配置和截图始终保留。
- 第一正式版不包含自动更新；签名与自动启动安装逻辑另立任务，不默认索取证书或管理员权限。

## 11. 主要风险与决策门

| 风险 | 决策门 |
|---|---|
| DComp 透明顶层窗口在多 DPI/输入穿透下行为不一致 | 技术原型必须在用户机器验证，否则停止并保留旧版 |
| 自绘笔迹与 Microsoft.Ink 的平滑/压感观感不同 | MVP 由用户用固定鼠标笔迹集与旧版并排比较，主观自然、响应不劣化即可；压感质量无设备时标未验证，不阻塞当前发布 |
| 自绘工具栏/选项工作量膨胀 | 先复刻现有布局和交互，不增加新 UI 功能 |
| 240Hz 测量被回调频率误导 | 必须采集可见呈现与 DWM 时间戳 |
| 新配置损坏用户旧数据 | 所有导入只读；新配置独立目录并有迁移测试 |
| 真实笔/触摸/多屏行为无法在当前设备验收 | 自动化覆盖可模拟部分，未验证项明确保留；不得用鼠标模拟冒充通过，也不要求无限期等待设备 |

## 12. 工期量级

完整对齐而非演示版预计 **20–30 个有效开发日**：技术验证 2–3 天、可书写 MVP 5–7 天、其余工作流 5–7 天、截图贴图 3–4 天、硬化与发布 5–9 天。真实压感笔、多显示器和兼容性问题的修复可能增加时间；每阶段结束都重新评估，不用赶工跳过验收。
